## 门① 位等价(代码未变 → 连续 rebuild 零副作用)

对三源各自:迁移重建(存量族无 `.rev`,版本戳腿触发,纪元 3→4,计数
不变)→ 快照(sidecar 字节 + 纪元目录清单 + 逐文件 sha256 + mtime_ns)
→ 再 rebuild → 快照逐位相等。**结论:增量跳写语义保住——数据未变+代码
未变时,不重建、不重开 reader、不碰任何 sidecar mtime。**

## 门② 消融(touch 前后 × 版本戳机制)

对照两路径(同 csv 字节、同代码):
- **旧仪式**:touch csv(mtime 腿)→ 强制重建;
- **C2 机制**:进程内 `HARVEST_REV +1`(模拟 harvest 代码演进),csv
  mtime 全程不动 → 版本戳腿强制重建。

| 源 | v4/v6 计数(touch 路径) | 计数(rev 路径) | 排除/告警日志 | mtime 不动 |
|---|---|---|---|---|
| myip_ms | 1563 / 56 | 1563 / 56(相等) | 0 行 = 0 行 | ✓ |
| ziyadnz | 123106 / 0 | 123106 / 0(相等) | 46 行 multiset 相等 | ✓ |

**结论:版本戳机制产出与 touch 强制重建逐计数相等、日志 multiset 相等
——touch 不再必要;代码演进无需动数据文件即触发真重建。**rev 前进后
`.rev` 已= 新代,再 rebuild 零副作用,无循环。
