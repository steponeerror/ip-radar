# SKILL — ipradar 发现管线演化(提案者工作技能)

你在演化 ip-radar 的**情报源发现管线**:一条 SCAN→SHORTLIST 的搜索回路,任务是从
自由 web 检索里找出值得接入的开源/公开 IP 情报源。基准世界用它当前的真实能力给你打分。

## 基准世界(你被度量的地方)

- **考题**:53 个已接入源(61 roster − 8 内部/派生免考)。每个源是一个任务 x,
  劈分冻结:40 演化集(演化反馈用)+ 13 留出集(终局验收用,你永远不会看到它的反馈)。
- **一次 trial**:管线跑一轮盲搜(沙箱:`dev/bench-rediscover/<roundId>/`,相位截断
  SCAN→SHORTLIST→CLOSE),产出 `d2-shortlist.json` 候选清单(名/URL/一句话理由)。
- **打分**:对每个考题源,候选按四层匹配判命中——完整 URL → 发布者/域名 → 名字
  归一化 → 别名表。命中=1,未命中=0;**S = 逐源召回率**。免考源命中只留痕不入分;
  表外新候选( roster 之外的好发现)单独成清单,是加分项不是分母。
- **盲测纪律**:答案只在打分时用。你手里的证据 = 打分报告(谁命中谁落空、落空源
  附近出了什么候选)、轮工件、护栏结果。**永远不要试图把考题名单写进管线**——
  那是泄漏,leak gate 与审查者都会拦,泄漏候选一律作废。

## 你能改什么(开放面)

`ops/agent`(发现管线 v1 提示词/工具/fixtures)与 `ops/agent-v2`(durable 底座:
entry/registry/tasks/bench 全套)。红线与免碰面见 PATTERNS.md——尤其:**真实轮
路径行为必须字节级不变**(golden 钉),你演化的是基准轮能力,不是生产轮行为。

## 工作循环

1. 读分析师报告(落空源的失败模式)+ 逐任务摘要 + 编辑历史(已被拒绝的机制是
   负证据,不要原样重提)。
2. 提 ≤b_t 个可归因编辑(每个编辑一个假设:「这个改动预期救回哪些落空源」),
   编辑预算随轮退火——晚轮只允许单点改动。
3. 候选过三护栏才算活:golden(`ops/agent/golden/run-golden.mjs`)+ v2 全套
   (`npm test`)+ leak gate(`bench/leak-check.mjs` exit 0)。
4. 本接线期只有 faux 冒烟轮(罐装模型面,零网络零花费);真实 GLM 轮是花钱面,
   由人批准后单独跑。你的编辑要同时经得起两种模式的护栏。

## 心法(域内先验)

- 落空源的三种死法:①候选宇宙根本没覆盖(检索词/渠道面窄);②候选在场但没进
  短名单(聚合/去重/排序吞了它);③进了短名单但匹配层落空(名字归一差一步、
  域名给了仓页没给直链)。先诊断层位,再动刀。
- github 家族(raw.githubusercontent.com / github.com)同主机多源,靠 repo 路径段 禁词引用:匹配器判据引用(同 score.mjs github 家族区分判据)
  (owner/repo)区分——检索策略给了仓页 URL 也是命中面,给了错 repo 不是。
- 宁少算勿多算:同一证据(同一 URL 被多次给出)不重复计数;回声不是印证。
